# Workflow health

Use `$vl-workflow-health` in Codex when discovered, or read and apply this source.
Other hosts use their supported invocation or the same source fallback.
Normal automatic discovery remains enabled. On-demand use creates no schedule or permanent seat.
This audit reports evidence and proposed corrections. It adds no score, tracker, mandatory gate or approval stage.

## Shared communication

Read and apply the full [vl-adhd writing policy](../vl-adhd/SKILL.md) and
[vl-present presentation contract](../vl-present/SKILL.md) at entry.
Identify an unknown host before choosing invocation syntax.
Apply these contracts to all authored prose.
Preserve facts, uncertainty, permissions and stop/verification gates.
Explicit formats and fixed output contracts win. Presentation grants no new authority.

## Bound the request

Read the target repository's `docs/project-tracking/GITHUB-PROJECTS.md` configuration.
Declare the repo, product board, hosts, topic, source heads, observation time and bounded sample before the audit.
Name exclusions and inaccessible evidence. Missing access is unverified, not evidence of health or failure.
Stop at the declared sample. Report unanswered questions instead of silently expanding into every issue, transcript or repository.

Read and apply these sources before dependent findings:

- [vl-adhd](../vl-adhd/SKILL.md) for shared writing and [vl-present](../vl-present/SKILL.md) for presentation.
- [vl-product-map](../vl-product-map/SKILL.md), selecting intended/observed evidence pairing, timestamps and frozen-history exemptions.
- [vl-history](../vl-history/SKILL.md), selecting representative attempts, attribution and merged-versus-verified distinctions.
- The [shared Planner contract](../vl-plan/references/planner-contract.md) and [impact/verification contract](../vl-plan/references/impact-verification.md).
- [vl-handoff](../vl-handoff/SKILL.md) for context recommendations and preserved lifecycle state.

Use only the relevant portions of the audit instruments. Do not activate their whole-product or full-history modes by default.
Read applicable host adapters, repo instructions and current issue amendments where the sample requires them.
If a required source is unavailable, stop the dependent conclusion and record the missing evidence.
Loading a source does not activate its seat or expand this audit's authority.

## Compare evidence

Inspect these dimensions within the sample:

- **Instructions:** compare precedence, scope and dated supersession across shared policy, repo instructions, host rules and amendments.
  Cite both sides of a conflict. Treat frozen history and deliberate product invariants separately from drift.
- **Adoption:** distinguish approved, implemented, merged, generated, installed, discovered and actually used states.
  Retain observation dates and exact revisions. An accepted PR, generated folder or junction proves only its own stage.
- **Verification:** compare component passes with the actual user entry, persistence and integration acceptance.
  Identify skipped/disabled checks and runtime URL/build/head, mode, conversation, provider and service provenance where relevant.
  Apply the existing impact contract. Do not invent a universal UI or provider smoke.
- **Coordination:** inspect exact owners, durable handoffs, substantive consumption, pending decisions and supported wake liveness.
  Reuse the [board-intake contract](../vl-orch-codex/references/board-intake.md) where applicable.
  Transport acceptance is not a ruling. Separate policy gates, transport failures, runtime defects and context problems.
- **Process cost:** examine repeated unchanged work, redundant reviews, human confirmations, verification breadth and queues without usable outcomes.
  Cite practical effects. Counts alone establish neither waste nor quality.
- **Context:** inspect current relevance and concrete drift at a safe work boundary, using the handoff checkpoint below.

Use these evidence classes per claim:

- **Verified source:** directly read this run, with exact source revision or timestamp.
- **Observed execution:** action exercised and result observed this run, with its environment and limits.
- **Reported outcome:** an attributed earlier audit, PR result or execution record, with its original date.
- **Inference:** a stated interpretation supported by linked evidence, with uncertainty retained.
- **Unverified:** missing access, provenance or confirmation. State the exact remaining check.

Reading an earlier audit verifies that record, not the product sources or execution described within it.
Do not infer intrinsic host/model superiority or test value from unmatched histories or totals.

## Report and route

Lead with the most consequential observed gap and its practical effect.
For each finding, give intended contract, observed evidence, evidence class, existing owner and smallest proposed correction.
Give exact paths, heads and issue/comment links where available.
Keep matched specialization and coverage limits visible. Do not certify an entire workflow from a bounded sample.

Before recommending new work, search targeted open and closed issues and relevant history for existing ownership.
Record query scope, results and limits. An incomplete search is not evidence of absence.
Prefer the existing owning issue. Route implementation through its owning orchestrator.
Reports grant no filing, commenting or messaging authority.
Before external writes, establish explicit caller authorization naming the permitted destination and scope.
Preserve exact-ID messaging, durable issue recording and pending-ruling rules from the existing coordination contracts.

The audit does not repair sources, dispatch workers, resume stopped seats, change services or touch credentials.
It grants no provider calls, paid execution, automation, merge or deployment authority.
Preserve existing safety, financial, repair and website/publication holds.
For a real decision fork, give costed options and a recommendation through the existing owning issue.
Stop dependent action until the authorized ruling exists.

## Context checkpoint

Use the existing [vl-handoff checkpoint](../vl-handoff/SKILL.md#shared-checkpoint) at a natural boundary.
Choose continue, supported built-in Compact, or a fresh-chat handoff with a short evidence-based reason.
Age, turns, transcript size and compaction counts alone do not justify replacement.
Look for repeated forgotten decisions, confused identities/ownership, repeated resolved investigations, stale alternatives or repeated operator reconstruction.
Distinguish isolated errors from recurring drift and stale installed policy from context contamination.
A fresh chat does not inherently repair policy, transport or runtime defects.

Continue when relevant decisions, ownership and constraints remain accurate.
Recommend built-in Compact when continuity remains useful but stale exploration obscures the active task.
Before recommending fresh chat for persistent drift or material scope change, save the complete handoff and starter under existing authority.
If write authority is missing, report the save as pending and do not recommend transfer as ready.
Use vl-handoff's archive-safety assessment and exact old-owner identity. Unknown archive safety means keep the old owner unarchived.
Preserve pins, repair counts, holds, approvals, pending verification, exact issues/PRs/heads/branches/worktrees, workers, locks and environment ownership.
The successor reconciles current state before action. Do not duplicate workers or abandon active repairs to shorten context.
This skill creates no chat, performs no compaction, archives nothing and transfers no ownership.

For an attributed bounded example and illustrative context cases, read [the dated evidence receipt](references/2026-10-21-bounded-example.md).
It demonstrates instruction handling, not product execution, measured model performance or host compaction.

## New-model recalibration

If the request concerns a new model or routing recalibration, return execution to the owning orchestrator.
Require its full [routing and repair contract](../vl-orch-codex/references/model-routing.md).
That existing route screens independent benchmark evidence, challenges the lowest applicable proven seat,
and uses the smallest matched fixture for local confirmation.
Paid execution remains operator-only. Its sanitized evidence belongs on `/evaluation` under existing publication authority.
This audit grants no execution or publication authority and preserves current pins, financial holds and acceptance gates.
