# Controller contract proof — issue 357
Created: 2026-10-07. Last updated: 2026-10-07.
Issue: https://github.com/jerrodtuck/vilya/issues/357

This proof checks the controller contract before further paid work. It is synthetic infrastructure evidence. It does not compare model quality, report measured generation tokens, establish provider billing, or reset a live reservation.

The callable runContractProof function uses two fresh disposable copies of the immutable behavior fixture at seed 3d868ea5e69a3d01e433488ea6a682574d03a697. It uses a temporary offline ledger with the existing dated rate catalog and an injected deterministic provider. No provider transport, credential lookup, dependency installation or image build occurs. Every scripted call declares input 128, cached input 16, cache write 8, output 40 and reasoning 10 tokens. These counters test accounting; they are not measurements of model work. Costs calculated at fixed rates are synthetic microdollars, not actual charges.

A follows Sol/medium planning, Sol/medium implementation and Sol/high review. B follows Astra/high planning, then Sol/medium implementation, Sol/high review, one Sol/medium repair and a fresh Sol/high review. The first B review rejects an omitted explicit html-suffix regression even when the fixed gates pass. The repair adds that regression. Both reviews inspect the controller's actual before/after hashes, exact diff, immutable rubric and required gate set. They are scripted checks, not independent model reviews.

The main proof uses the production runTrial, hash-bound applyEdits and default acceptance function. Actual Docker execution uses the cached behavior image sha256:d27234200476cde5d5edd79ee422fdbfbf1676063ef7b91963c653958b960106 and its pinned dependencies. Containers have network none, read-only base/dependencies, a non-root user and bounded temporary writable files. Each attempt runs the same focused, oracle, sync-projects, sync-skills, tests, build and spacing gates. The proof checks terminal receipts, routing, failed-review and repair history, complete synthetic usage/cost, elapsed time and confirmed container cleanup.

Public evidence is validated in memory through publicSnapshot and assertAcceptedEvidence. It is never exported to the website. The separate proof report labels every result synthetic and records the controller revision, fixture seed, image digest, timing, route, synthetic counters/cost and limitations. Disposable evidence remains available for review.

Run the actual proof with node scripts/evaluation/contract-proof.mjs. The equivalent integration test requires EVALUATION_DOCKER_CONTRACT=1 and scripts/tests/evaluation-end-to-end.test.mjs. Ordinary source tests use explicitly injected component gates and skip the Docker proof unless enabled. Component cases cover malformed edits/review, a failed required gate, two unsuccessful corrections, request/input limits and phase-budget/time denial before later sends. Passing component cases do not establish actual sandbox execution.

Any unexpected provider, packet, schema, gate or cleanup failure fails the proof. A production defect requires a precise reproduction and a separate settled remediation plan. Existing paid financial admission repair history and held funds remain outside this proof. Root-owned frozen metadata checks and independent review remain required before further paid work.

Observed verification: the initial actual Docker proof used controller revision ddde35e33d4c70786df490a4628b46801b0b103e and completed in 37,592 ms. A completed one full gate attempt in 14,347 ms; B completed two in 22,588 ms. Synthetic accounting was 1,890 and 5,676 microdollars respectively, with zero held synthetic funds. All three full gate sweeps and container cleanup passed. This is contract evidence only.

The initial component run separately exposed a terminal receipt defect: malformed reviewer JSON could remain assigned before validation, causing a later TypeError when constructing the failure receipt. The bounded correction validates a local candidate before assigning review metadata. Empty/null/invalid JSON, wrong ready/findings types and non-string findings now preserve a closed failed terminal receipt, completed synthetic usage/cost, no raw response text and no additional phase calls. Initial detection and the successful first corrective verification remain part of the evidence history; they do not reset any live billing repair count.
