## Scope and evidence

All shipped source skills are enumerated below, including the new Codex orchestrator.
The four quoted string fields in each SKILL.md are Vilya registry metadata, not native
Codex configuration keys. Source is `skills/<slug>/SKILL.md`; generated copies live in
`apps/skill-registry/content/skills/<slug>/SKILL.md`. A directory without SKILL.md
(such as `skills/tests`) is not a shipped skill. The contract suite checks exact set
equality, metadata, invocations, links and generated bytes; counts are observations,
not a fixed catalog limit.

Evidence read on 2026-10-03:

- [Build skills](https://learn.chatgpt.com/docs/build-skills): skill manifests and discovery.
  Explicit source read/apply is the documented fallback in these procedures when a
  skill is not in the live selector. Actual installed discovery remains an integration check.
- [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees): checkout and
  ignored setup background. Current app tools govern create/attach/archive details.
- [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): delegation
  background; current session tool contracts, rather than a generic page, govern the
  exact fork/model and shared-filesystem constraints used here.
- [Model selection](https://developers.openai.com/api/docs/guides/model-selection):
  capability/cost guidance. #329's approved role policy maps planning to the current
  highest-capability family and implementation to the balanced workhorse family.
  Exact supported identifiers/effort are resolved at dispatch; explicit human overrides win.
- Live session contracts reviewed: native collaboration spawn/message/follow-up/wait/list/
  interrupt; app managed create/status/attach/archive/restore; PR attachment; cross-chat
  messaging requiring trusted human authorization in each sending seat. No calls to
  unavailable Claude or Cursor host tools are claimed.

## Host audit and routing boundaries

- `vl-chip`, `vl-merge-pr` and `vl-prune` explicitly admit only the three orch
  seats; architect, router, planner and workers retain their denial boundaries.
  Their early Codex paths precede legacy host procedures. `vl-start-feature` replaces
  worktree/model/Planner/monitor sections only for Codex; shared issue, architecture,
  fork and verification obligations still apply.
- `vl-arch` remains direction-only. Its Codex entry, the Codex orch entry and worker
  brief/finish entry each state trusted same-board initiation/reply prerequisites,
  counterpart role/board/repo/identifier selection and durable issue recording.
  Peer messages grant no reply, decision, model, implementation or merge authority.
- `vl-ask` routes Codex planning to the orch. Other-host standing seats and Worker A
  stop before their Codex-inapplicable procedures. The blanket Cursor messaging
  impossibility claim in Worker A is replaced with an explicitly unverified capability
  boundary; its issue/PR coordination procedure remains unchanged.
- Managed creation uses explicit refs, readiness/registration and absolute checkout
  verification. Ignored setup is verified and preserved. Managed archival uses exact
  attachment identities and respects tool restrictions; legacy removal/kill flows are
  unreachable on that path. No new unattended backend or eligibility change.
- Shared review contracts retain all architecture, severity, remediation and readiness
  requirements. Codex may read/apply these sources directly; source reading is not a
  claim that a native slash chain or another host's skill runner exists.

## Sidebar grouping amendment

The 2026-10-03 operator amendment requires explicitly requested sidebar workers in
exactly `<repo-short>-orch-working`. The Codex orch and chip contract name native
list/create/move/rename tools, require section reuse and final verification, and
preserve created workers on tool failure. Claude/Cursor seats apply the convention
only with equivalent exposed capabilities. Organization grants no creation/messaging
authority or checkout isolation. Actual grouping execution remains runtime evidence
on #329; the source suite checks the required contract and merge-gate enforcement.
